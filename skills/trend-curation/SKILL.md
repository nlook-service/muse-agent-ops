# trend-curation

## Purpose
매일 아침 정해진 소스들에서 최신 기사 1편씩을 수집해
상세 요약 문서로 만들어 문서 서비스에 등록한다. (하루 최대 6편)

## Workflow

### 1. 수집 소스 (소스별 1편씩)
1. **디에디트**: RSS에서 어제~오늘 발행 글 중 1편
2. **해커뉴스**: topstories API에서 최근 24시간 이내 1편 (원문 URL의 og:image 확보)
3. **긱뉴스**: Atom 피드에서 최신 1편 (og:image 확보)
4. **커뮤니티형 매거진**: 최신 글 확인. 넘버링 리스티클 중 최근 3일 이내 발행된 것이 있을 때만 1편, 없으면 건너뜀
5. **라이프스타일 매거진**: 트렌드·마케팅 관련 기사 1편
6. **IT 아티클 플랫폼**: 최신 아티클 1편

한 소스가 실패해도 나머지는 계속 진행한다.

### 2. 중복 방지
등록 전에 최근 등록 기사를 태그로 조회하고, 이미 등록한 URL의 기사는 제외한다.

### 3. 문서 작성 (기사별 1개)
- **제목**: 기사 제목 그대로 (제목에 링크를 걸지 않는다)
- **태그**: `["trend-daily", "<소스 슬러그>"]`
- **내용 구성** (순서 준수):
  1. 기사 제목 첫 줄
  2. `- **출처**:` / `- **발행일**:` / `- **원문 보기**: [원문URL 전체](원문URL 전체)` — URL은 텍스트로 완전히 보이게 표기 (이 줄이 없으면 미완성)
  3. 대표 이미지 1장 `![설명](이미지URL)` — 반드시 포함. 못 구하면 이유를 말미에 한 줄
  4. **상세 요약**: 기사 흐름을 따라 4~7문단. 핵심 팩트(숫자·고유명사·날짜) 빠짐없이. **원문을 통째로 옮기거나 문장 단위 패러프레이징은 저작권상 금지 — 자신의 문장으로 요약**
  5. **핵심 포인트** 6~8개: `**소제목** — 구체적 설명` 형식
  6. **왜 주목할 만한지** 1~2문장
- 표(table) 금지, 이모지 장식 금지, 강조는 볼드

### 4. 등록
문서 API로 등록하고 성공 여부를 출력으로 확인한다.

### 5. 보고
짧게: 수집한 기사 수, 소스별 제목 1줄씩, 실패한 소스가 있으면 이유.

## Operating Rules
1. 유료 구간은 요약하지 않고 공개분만으로 작성, 원문의 10% 이상 인용 금지
2. 짧은 요약은 부실 판정 — 4~7문단 상세 요약을 지킨다
3. 소스별 실패는 건너뛰고 계속 진행, 같은 날 재시도하지 않는다
4. 인증 오류 시 해당 서비스의 Auth 절차를 따른다
