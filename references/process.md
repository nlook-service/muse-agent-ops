# 신규개발 파이프라인 v2

## 단계와 전이 조건

| 단계 라벨 | 의미 | 다음 단계로 넘어가는 조건 |
|---|---|---|
| `단계:기획중` | 기획서 작성·컨펌 리뷰 중 | 컨펌 리뷰 "통과" 판정 |
| `단계:디자인중` | 디자인 시안 제작 중 | walter(또는 담당자)의 시안 컨펌 |
| `단계:개발대기` | 기획·디자인 완료, 개발 시작 대기 | `@claude` 트리거 또는 명시적 승인 |
| `단계:개발중` | 개발 진행 중 | PR 머지 → 이슈 close → Done |

규칙:
- 단계 라벨은 이슈당 **1개만** 유지한다. 전환 시 기존 것을 떼고 새 것을 붙인다.
- `기획완료`·`디자인완료` 같은 완료 마크는 쓰지 않는다. `단계:개발대기`가 그 역할을 대신한다.
- 개발 단계에서는 이슈 하나 = PR 하나 = 검증 방식 하나.

## 보드 매핑 (ProjectsV2 Status)

| Status | 해당하는 단계 |
|---|---|
| Todo | 라벨 없는 신규 이슈 |
| In Progress | 기획중·디자인중·개발대기·개발중 |
| Done | close된 이슈 |

## 마일스톤

- 월간 분야 마일스톤을 쓴다: `기획 10월`, `디자인 10월`, `개발 10월` …
- 단계가 바뀌면 마일스톤도 함께 옮긴다: 기획중→기획 10월, 디자인중→디자인 10월, 개발대기/개발중→개발 10월.
- 에픽 이슈는 별도 마일스톤(기능 단위)을 쓴다. 마일스톤 100% = 기능개발완료.

## 분야 라벨

`분야:기획/개발/마케팅/디자인/인프라/QA/운영/사업운영/자금/AI기술` — 이슈의 성격 분류.
하나의 이슈에 여러 분야가 붙을 수 있다(예: 기획+디자인).

## 우선순위

`P0`(당장) / `P1`(이번 주·이번 달) / `P2`(여유) / `P3`(나중).
`직접확인필요`는 자동화 확신 게이트 탈락 시 붙는다. 사람이 직접 답해야 넘어간다.

## 자동 유지

3시간마다(또는 팀이 정한 주기) `bin/hygiene.py`로 점검:
1. 분야 라벨 누락 → 제목의 `[태그]`로 추론해 제안
2. 마일스톤 미지정 → 단계에 맞는 월간 마일스톤 제안
3. 단계 라벨 0개·2개 이상 → 1개로 정리
4. 보드 상태와 단계가 다르면 보드 업데이트

`--apply` 없이 실행하면 dry-run으로 무엇을 바꿀지만 보여준다.
