# 실전 활용 가이드

이 스킬들을 실제 업무에서 어떻게 쓰는지, 상황별로 정리했습니다.

## 시나리오 1: 새 프로젝트 시작하기

새 레포를 만들었는데 이슈 관리 규칙이 없을 때.

```bash
python3 bin/install.py --skills pm
# 대상 레포 입력 → 라벨 21개 설치
```

이제 이슈를 만들 때마다 `분야:` 라벨을 붙이고,
신규 기능이면 `신규개발` + `단계:기획중`을 붙입니다.
기획이 끝나면 `단계:디자인중`, 시안 컨펌이 나면 `단계:개발대기`.
이슈 목록만 봐도 각 기능이 어디쯤인지 보입니다.

## 시나리오 2: 1인 기업의 아침

직원이 없는 1인 기업. 아침에 이슈 38개를 다 열어볼 수 없습니다.

```
Muse에게: "열린 이슈 현황 정리해줘"
→ 단계별 개수, 막힌 것(직접확인필요), 이번 주 마감이 있는 것을 보고
```

`hygiene.py`를 주기적으로 돌리면 라벨·마일스톤이 자동으로 정리됩니다.
"지금 어디쯤이에요?"라는 질문을 받지 않게 됩니다.

## 시나리오 3: 외주·팀원과 함께 쓰기

"우리 팀 규칙"을 말로 설명하는 대신 레포를 가리킵니다.

```
"이 레포 보세요. setup.py 돌리면 우리랑 똑같은 규칙이 깔립니다."
```

라벨 이름부터 파이프라인까지 동일해지니,
"기획 끝났어요"가 무슨 뜻인지 설명할 필요가 없습니다.
`단계:개발대기` = 기획·디자인 끝, 개발 시작 가능. 끝.

## 시나리오 4: 영어 학습 루틴 자동화

매일 아침 영어 기사를 골라 학습 문서를 만드는 루틴.

```
Muse에게: "english-learning 스킬로 오늘 아침 학습 문서 만들어줘"
→ 뉴스 선정 → 이미지 → 학습 문서 작성 → 등록 → 보고
```

백엔드는 로컬 파일로 시작해도 됩니다.
나중에 nlook이나 다른 문서 서비스로 바꿀 수 있습니다.

## 시나리오 5: QA 이슈를 정확히 남기기

"설정 화면에서 이상해요" 같은 이슈는 개발자가 다시 물어봐야 합니다.

`qa` 스킬의 규칙대로라면 이슈에는 반드시 4개가 들어갑니다:
URL · 메뉴 경로 · 화면명+문제 부위 · 스크린샷.
하나라도 빠지면 등록 자체를 안 합니다.

## 시나리오 6: Claude Code 세션 24시간 유지

iPhone으로 외출 중에 코딩하고 싶을 때.

```bash
# 한 번만 설치
python3 bin/install.py --skills claude-keepalive
```

이후 VM이 재시작돼도 Claude 세션이 자동으로 살아납니다.
집 컴퓨터가 꺼져 있어도 원격 코딩이 계속됩니다.

## 조합해서 쓰기

| 조합 | 효과 |
|---|---|
| pm + qa | 이슈의 생애주기 전체를 규칙으로 관리 |
| english-learning + trend-curation | 아침 루틴: 학습 + 트렌드 파악을 문서로 |
| pm + claude-keepalive | Claude가 개발하는 동안 PM 정리는 Muse가 |
